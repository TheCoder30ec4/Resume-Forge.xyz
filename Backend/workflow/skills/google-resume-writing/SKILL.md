# google-resume-writing

Use this skill when writing resume bullets and section content. Bullets that follow these rules pass the bar at top-tier hiring committees; bullets that don't get filtered.

## The XYZ formula (the core rule)

Every accomplishment bullet should follow:

> **"Accomplished [X] as measured by [Y], by doing [Z]."**

- **X** — the impact: what you achieved, the business outcome, the user-facing result
- **Y** — the measurement: a number, percentage, ranking, time saved, money saved, scale
- **Z** — the action: the specific technical work you did, the methods, the tools

### Examples (good)

✅ "Reduced p99 API latency from 800ms to 220ms (Y) by profiling Python services and migrating hot paths to Go (Z), unblocking the payments team's SLA commitments (X)."

✅ "Cut customer onboarding time by 47% (Y) by automating manual KYC steps with a Python+Postgres pipeline (Z), enabling the company to launch in 3 new markets (X)."

✅ "Designed a sparse attention mechanism reducing transformer memory by 4.2x (Y) by replacing dense softmax with a learned routing module (Z), enabling on-device deployment (X)."

### Examples (bad — rewrite these)

❌ "Worked on backend services" — no X, no Y, no Z
❌ "Responsible for improving performance" — passive, no measurement
❌ "Used Python and Docker" — Z without X or Y
❌ "Helped the team be more productive" — vague, no number

## The five rules

### Rule 1 — Length

- **Roughly one page per ten years of experience.** A new grad has one page; a senior with 12 years has 1-2.
- **Never go past two pages** unless you're an academic with a publication list.
- Cut content ruthlessly to fit. Every bullet earns its space.

### Rule 2 — Format consistently

- Same font, same size, same style throughout.
- Same date format throughout (e.g., `Sep 2023 – Present`, never mixing `09/2023` and `September 2023`).
- Aligned columns for dates and locations.
- Reverse-chronological order within each section.

### Rule 3 — Use the XYZ formula on every accomplishment bullet

See above. If you can't write a bullet in XYZ form, the work probably isn't strong enough to include.

### Rule 4 — Quantify EVERYTHING

If a number exists, use it. If you don't know the exact number, estimate honestly and use a range. Examples of metrics worth including:

- **Money**: revenue impact, cost saved, budget managed
- **Time**: speedup, latency reduction, hours saved per week, days off the critical path
- **Scale**: users served, requests/sec, dataset size, team size led
- **Quality**: error rate reduction, accuracy improvement, NPS lift, churn reduction
- **Adoption**: number of teams adopting, number of repos depending, GitHub stars
- **Recognition**: rank in cohort, paper acceptance rate, award percentile

If a bullet has zero numbers, ask: "Can I add one?" If genuinely no, the bullet is probably about scope or responsibility — fine, but should be the exception.

### Rule 5 — No typos, no inconsistencies, no lies

- Proofread three times. A single typo gets the resume rejected at top-tier firms.
- Verify every number you cite. If interviewer asks "how did you compute the 73%?", you must be able to answer.
- Consistent verb tense: past tense for past roles, present for current role.

## Action verbs (use these, not "responsible for")

**Built/Created**: built, designed, developed, engineered, architected, prototyped, launched, shipped
**Improved**: optimized, accelerated, reduced, streamlined, refactored, migrated, scaled
**Led**: led, drove, owned, spearheaded, founded, coordinated, mentored
**Analyzed**: analyzed, evaluated, modeled, measured, audited, profiled, benchmarked
**Solved**: resolved, debugged, root-caused, eliminated, fixed

## Avoid these phrases

- "Responsible for..." — passive, no impact
- "Helped..." / "Assisted..." — minimizes your contribution; if you helped, say what you specifically did
- "Worked on..." — what did you build, ship, fix?
- "Various" / "multiple" / "several" — name them or count them
- "Team player" / "self-starter" / "detail-oriented" — adjectives without evidence; let the bullets prove it

## Sectioning recommendations

For software engineering / technical roles:

1. **Header** — name, location, email, phone, LinkedIn, GitHub. No photo for ATS. Keep it tight.
2. **Summary** (optional, 2-3 sentences) — only useful for senior+ roles or career transitions. Skip for new grads.
3. **Experience** — reverse chrono, last ~10 years. Each role: company, title, dates, location, 3-6 XYZ bullets.
4. **Projects** — the 2-4 most impressive personal/OSS projects. Same XYZ rule applies.
5. **Education** — degree, school, dates, GPA if 3.5+, relevant coursework only if recent grad.
6. **Skills** — grouped (Languages, Frameworks, Infrastructure, Tools). Be honest — no skill listed unless you can answer questions on it.
7. **Optional**: Publications, Patents, Honors, Talks — only if substantive.

## Tailoring to a specific JD

Top-tier companies expect tailoring. For each application:

1. Identify the JD's top 5-10 keywords (skills, frameworks, methodologies).
2. Ensure each appears in the resume verbatim, in context (in a bullet, not just a skills list).
3. Reorder bullets within each role so the most JD-relevant work leads.
4. Drop bullets that don't connect to the JD if you're over the page count.

## Final review checklist

Before submitting:

- [ ] Every bullet has at least one number (or a deliberate qualitative reason it doesn't)
- [ ] Every bullet starts with a strong action verb (past tense unless current role)
- [ ] All dates use the same format
- [ ] All section headers use the same style
- [ ] No typos (run a spellchecker, then read it backward)
- [ ] Fits on one page (or two if 8+ years experience)
- [ ] Tailored to this specific JD's keywords
- [ ] Every claim is true and defensible in interview
